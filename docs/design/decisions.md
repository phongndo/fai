# Decision log

## Decided

| Area | Decision | Rationale |
|---|---|---|
| Architecture | The Lean 4 spec is the source of truth; the production compiler is in Rust, with a self-hosted implementation as the long-term goal | Proofs need a precise reference; the spec outlives any one implementation language. Rust is chosen for correctness first: memory safety and data-race freedom rule out whole bug classes in the compiler itself, and exhaustive `match` on op kinds catches missing cases at compile time |
| North star | Semantics as the platform | See [00-north-star.md](00-north-star.md) |
| Scope | General-purpose target. The first phase is the AOT compiler only, with a C subset as the first frontend. JIT, VM embedding, and web (Wasm) are later phases; see [Phasing](00-north-star.md#phasing) | One execution mode keeps the first phase small, and the core is designed so later phases don't change it. C has the hardest well-understood UB and large existing test corpora |
| Layers | HFIR / MFIR / LFIR as fixed contracts, with the target legality rule. Each op's declaration lists the layers that allow it (`layers hfir mfir`, the default). A module states its layer (`layer hfir`, `layer mfir`, `layer lfir aarch64`; HFIR when absent, and printed only when not HFIR), and the verifier rejects an op outside it before any other check. Today's core ops are in HFIR and MFIR, except `ptr.field` and `ptr.index` (HFIR only), and of the building blocks `agg.make`, `agg.extract`, and `agg.insert` are in MFIR too, for the structs and arrays calls pass whole (decision: C ABI for aggregates); LFIR for a target allows the target's dialect and, of the core ops, only `func.ret` | See [01-layers.md](01-layers.md). Declaring layers with the op keeps both verifiers enforcing the same contract. HFIR as the default keeps existing and hand-written modules valid. MFIR addresses by offsets (decision: Layout), and functions need `func.ret` in every layer |
| Extensibility | Dialect-ready from day one: generic op representation, three trust tiers per op; dialects are declared op groups for now (see Dialects) | Retrofitting generic ops is costly |
| Next round | The C round: `fai-cc`, a C compiler on the builder API, with the IR features C still needs (floats, varargs, aggregates by value in the C ABI); see [04-plan.md](04-plan.md). The previous round built HFIR, MFIR, and LFIR down to AArch64 behind the builder API ([03-plan.md](03-plan.md)) | A real compiler on the platform shows where the API and the IR fall short; the trust round is easier to aim once one exists |
| First target | AArch64. Its instruction semantics come from Arm's machine-readable ASL (via the Sail model) in the trust round; this round writes them by hand | An official spec instead of a transcription; native on Apple hardware, `qemu-aarch64` on Linux |
| LFIR for AArch64 | Machine form: `aarch64.*` ops (layers `lfir`) name their registers as immediates (`x0`…`x30`, `sp`, `xzr`, and virtual registers `v0`, `v1`, … before allocation; FP/SIMD registers `d0`…`d31` and virtual ones `fv0`, `fv1`, …; a new op-table field type `Reg`, a `u32` in Rust whose top bit is the class, `FIR_REG_D0` and `FIR_REG_FV0` in C) and have no operands or results; the size (`.w`/`.x`, ASL's `sf`; `.s`/`.d` for FP, ASL's `ftype`, so `d3` is also `s3` as `x3` is `w3`), condition codes, and operations are modifiers in the name. A function's body is `aarch64.code { ^b0: … }`: labeled blocks without parameters, each ending in `aarch64.b`, `aarch64.b.<cond> ^t, ^f`, `aarch64.b.exn ^t, ^f`, `aarch64.ret`, or `aarch64.trap.<reason>`, with no fall-through. LFIR keeps `func.ret` only for a body that returns its parameters; `cf.blocks` stays out. The ops: three-register ALU (incl. `adds`/`subs`/`ands`, shifts by register, `mul`, `sdiv`/`udiv`, `smulh`/`umulh`), ALU with an immediate, shifts by an immediate, `sbfx`/`ubfx` from bit 0, `mov`, `movz`/`movn`/`movk`, `csel`/`csinc`/`csinv`/`csneg`, `ldr`/`str` of 1, 2, 4, 8 bytes at base plus offset, `adrl` (global or function address: `adrp`+`add`, or a GOT load for an external function), `bl`, `blr` (with the callee's signature), runtime calls `bl.alloc`/`bl.free`, and the exception slot's `exn.set`/`exn.take` (decision: Exceptions at run time). Scalar FP: `fadd`/`fsub`/`fmul`/`fdiv`, `fmov` (also between a general-purpose and an FP register, Arm's `FMOV (general)`), `fabs`, `fneg`, `fsqrt`, `fmadd` in accumulator form (`aarch64.fmadd.d d0, d1, d2` is `fmadd d0, d1, d2, d0`), `fmov.imm` with Arm's 8-bit encoding (`VFPExpandImm`), `fcmp` (the flags, then `b.<cond>`, `csel`, `fcsel`), `fcsel`, `fcvt.d.s`/`.s.d`, `scvtf`/`ucvtf`, `fcvtzs`/`fcvtzu`; `ldr`/`str` move FP registers too (`ldr.w` into `d0` is `ldr s0`). Register classes are checked when an instruction runs (the wrong class is stuck), with `fmov`, `ldr`, and `str` taking either. Which immediates encode is the emitter's concern, not the semantics'. For a call of a variadic function, `blr`'s signature lists every argument's type at the call (decision: Varargs) | SSA values can't name the physical registers that calling conventions, prologues, and spill code need; registers as immediates give one form before and after allocation, which both interpreters run, and the ASL describes instructions the same way (registers as fields of the encoding). Explicit blocks are what the hardware does; four-register ops (`madd`, `ldp`) are left out so `OpKind` stays 16 bytes, and `fmadd` takes the accumulator form for the same reason (instruction selection copies the addend into the destination first, one `fmov`). One field type for both classes keeps the op table, builder, and C API as they were; the class bit makes a register's class visible without its op |
| AArch64 semantics | `Fir.AArch64` gives each instruction's bits in ASL's shape (`AddWithCarry`, `ConditionHolds`, the `sf` size; for FP `FPProcessNaNs`, `FPMulAdd`, `FPConvert`, `FPCompare`, `FPToFixed`, `FixedToFP`, `VFPExpandImm` over `Fir.Float`'s arithmetic, with FPCR as Linux and macOS leave it: round to nearest, `DN`, `FZ`, and `AH` off), to be replaced by an import of Arm's ASL. A NaN result is Arm's: the first signaling NaN operand, else the first quiet one (`fmadd`'s addend first), made quiet, or the default NaN, which is FIR's canonical one, for an invalid operation; `Fir.AArch64Proofs` shows each FP result is one FIR's op allows (`fpAlu_allowed`, `fpSqrt_allowed`, `fpMulAdd_allowed`, `fpConvert_allowed`), that under `Oracle.arm` FIR's ops give exactly the instructions' results (`floatBin_arm` and friends), and that `fcvtzs`/`fcvtzu` are `float.to_int.*.sat` (`fcvtz_sat`). `Fir.AArch64Machine` runs LFIR over FIR's core (memory, allocations, events, oracle): registers hold *words*, 64 bits or a pointer with its provenance; FP registers hold 64 bits (the low half of `V0`…`V31`, all scalar code reads; a write of `s` or `d` zeroes the rest), and so do FP virtual registers. 64-bit `add`/`sub` of an integer, moves, `csel`, and 8-byte loads and stores of a pointer's eight fragments keep provenance; every other use reads the address (realizing it, as `ptr.addr`). Registers are never `poison`: uninitialized bytes and `poison` arguments read as oracle choices. Memory is flat: an integer address reaches the live allocation holding those bytes, exposed or not; lifetimes and bounds are checked, alignment and `noalias`/`readonly` scopes are not. The stack is one 1 MiB allocation with `sp` at its end. Virtual registers are per call; physical ones are global, and `ret` checks that `x19`…`x29`, `sp`, and `d8`…`d15` are as on entry (stuck otherwise). `ret` returns to the caller whatever `x30` holds. `fir-ref run` and `fir run` run `layer lfir aarch64` modules on this machine; existing proofs are untouched. An external function called by `blr` reads its arguments by `blr`'s signature (the call's argument types: decision Varargs), and a run of a variadic function from outside places its variadic arguments by their types | LFIR must be a refinement target for isel and register allocation, so it may only be more defined than MFIR: hardware has no `poison` and no provenance checks on integer addresses. Keeping provenance where it is cheap keeps pointer results and events printable like MFIR's. A separate machine, not new frame kinds in `Fir.Interp`, leaves every simulation proof as it is |
| Calling convention | AAPCS64 for integers, pointers, `bN` up to 64 bits, `f32`, and `f64` (`abi.rs`, Lean's `argLocs` and `resRegs`): integer and pointer arguments in `x0`…`x7` and float arguments in `d0`…`d7` (`s0`…`s7`), counted separately and in order, then 8-byte stack slots from `sp` in argument order (an `f32` in the low 4 bytes); one or two results in `d0`, `d1` when all are floats of one format (an HFA), otherwise in `x0`, `x1`, a float as its bits (`fmov`): how C returns a struct of the results as 8-byte fields (`double`, `float`, or a 64-bit integer); three or more in 8-byte slots at the address the caller passes in `x8` (C's rule for a struct of 64-bit fields larger than 16 bytes). A narrow integer is in the low bits of its register, the rest unspecified, as is an `f32`'s. Callee-saved `x19`…`x28`, `x29` (frame pointer, always set up), `sp`, and the low 64 bits of `d8`…`d15` (all FIR keeps in an FP register); the other FP registers are caller-saved; `x18` is never used. Frame: `x29` points at the saved `x29`/`x30` pair; below it the callee-saved registers, spill slots, locals (`mem.stack` slots, results areas), and the outgoing argument area at `sp`; `sp` is realigned when a local needs more than 16 bytes. Wider integers are rejected (`i128` would need register pairs); macOS's differences (stack arguments packed by size, callers extending narrow arguments) aren't handled yet. Variadic arguments go where fixed ones of their types would (AAPCS64 on Linux), counted on from the named ones, and a variadic function saves the argument registers its parameters leave over for `va.start` (decision: Varargs). Structs and arrays by value follow AAPCS64's composite rules, and stack placement is counted in bytes (decision: C ABI for aggregates) | Matches C for every signature of 64-bit scalars and floats, so C calls FIR and back (`tests/capi/e2e.c`: libm from FIR, FIR from C with stack arguments and both kinds of result pairs, `d8`…`d15` kept); narrow results packing like C structs (two `i32` in `x0`) would cost shifts on every multi-result return for no client yet. Each class counting its own result registers would save the `fmov` of a mixed pair, but no C function returns that way |
| C ABI for aggregates | **Where:** calls pass structs and arrays whole. Outside HFIR a value may be a *composite* (`Ty.isComposite`: a struct or array of scalars and composites, no unions or slices), made by `agg.make`, taken apart by `agg.extract` and `agg.insert` (now HFIR and MFIR ops), copied, and passed as a parameter, a call argument or result, a `va.arg` result, or a function's only result; a composite among several results, and loads and stores of composites, stay HFIR only. The lowering keeps composites whole exactly there (`Lower.makeWhole`, `Lower.extractWhole`: `agg.make` of the scalars where one is passed, `agg.extract`s where it arrives) and scalarizes everything else as before (several results, unions, slices, region state), so MFIR stays target-independent and names only the ABI's unit, and every function with struct or array parameters or a struct or array result (any FIR function may be called from C) has AAPCS64's convention for them. **AAPCS64** (§6.8.2, §6.9; `Fir.AArch64Abi`, twin `abi.rs`): an empty composite takes nothing; an HFA (`hfaOf?`: one to four floats of one format that tile it in memory, whatever order its fields are declared in, so a `struct<auto>` whose layout puts a later field first, or a nested packed struct, is classified as laid out, as GCC and Clang do; no zero-length array anywhere, which is GCC's rule; empty structs don't count) takes consecutive FP registers, one per member in memory order (isel keeps the permutation from leaves to registers, `abi::hfa_order`), if enough are left, else NSRN becomes 8 and it goes on the stack as its bytes, size rounded up to 8 (C.3); a composite of up to 16 bytes takes one or two `x` registers holding its bytes as `ldr`s from an aligned copy would load them, starting at an even register if it is 16-byte aligned (C.10), else NGRN becomes 8 and it goes on the stack, NSAA aligned to 8 (16 for a 16-byte aligned one), size rounded up to 8 (C.13–C.15); a larger one is copied by the caller into its own frame, and the copy's address travels as an integer argument (B.4), the callee reading (and owning) it. A composite passed as `x` register words whose pointer leaf doesn't fill a word (`Ty.splitsPtr`, twin `abi::splits_ptr`: a pointer at an offset that isn't a multiple of 8, which only a packed struct of at most 16 bytes has) can't be passed by value: instruction selection refuses it as a parameter, argument (to FIR or C), or result with a compile error, wherever the arguments before it leave it (registers or stack), since registers could carry such a pointer only as shifted address bits. Variadic composites are C composites, whose pointers fill words. A composite result comes back where it would be passed as the first argument, or in memory the caller passes in `x8`. Variadic composites go where named ones of their types would (Linux), and `va.arg` follows AAPCS64's algorithm: up to 16 bytes from the general-purpose save area (from an even slot when 16-byte aligned) or the stack, an HFA's members from the FP save area (a 16-byte slot each) or the stack, a large one through the pointer read as a general-purpose argument; once a class's offset turns positive the arguments after it are on the stack, as C.3 and C.13 placed them. On macOS a composite passed on the stack is a compile error (Apple packs stack arguments; register and `x8` placement is the same). **Semantics:** HFIR's are unchanged, and MFIR's composites are the same tuples of leaves (`RVal.agg`), so calls pass values, never bytes: padding has no value and a `poison` leaf stays `poison`. External functions take and give composites (decision: External functions); variadic composites are C's (`Ty.isCComposite`: nonempty `struct<C>` and arrays of scalars and such, whose layout a value's shape determines), each in a slot of its size rounded up to 8 holding its leaves' bytes, and `va.arg T` of a composite needs the argument's type up to `Ty.canon` (an array is the `struct<C>` of its elements), else it is UB `va-arg`, as is a scalar read of a composite argument or the other way. **Soundness** (native code refines the semantics): a composite's register pieces are its bytes (`pieces_flatten`). Any words that hold the pieces (`Word.Holds`: a whole pointer's eight fragments as that pointer, any other piece as bits agreeing with each of its defined bytes; the machine's word for a piece, `wordOfBytes`, is such a word whatever it picks for `poison` padding, `poison` leaves, and stray fragments: `Word.holds_fill` of `Word.fill`, its shape, which matching `wordOfBytes` is by inspection), stored back, give as many bytes with every defined one in place (`arrives`; `roundTrip` is the case of wholly defined pieces), and in a composite that doesn't split a pointer each pointer leaf is in its register as itself, provenance included (`ptrLeaf_inReg`). So every defined leaf arrives exactly, padding is whatever a register held, which no leaf reads, and a `poison` leaf is some value, which refines it. That instruction selection's packing makes words that hold the pieces (a pointer that fills a word moved without arithmetic, the other leaves' bits shifted and or-ed, padding zero) is tested, not proved: the torture test runs FIR's calls in the interpreter as MFIR and as LFIR and requires the same events, pointer provenance included. Byte leaves (`bN`) holding pointer fragments other than one whole pointer in a word still cross as their address bits, as byte values in LFIR registers do anywhere (decision: AArch64 semantics), so a `read(args)` callee can reach less through them in LFIR than in MFIR: open (no frontend makes byte leaves; `fai-cc` has no byte types). A large composite's copy is made per call in the caller's frame, so a callee's writes to its copy (which C allows) never reach the caller's value, as in the semantics, where the callee has the values. The LFIR machines read an external callee's composite arguments, and place its composite results, by `argLocs` and `resRegs`, decoding the leaves from the bytes as loads do | Keeping composites whole only across calls leaves the target-independent lowering without ABI knowledge and keeps MFIR's memory scalar, so `dse`, `fwd`, and their proofs see what they saw; the backend, which knows registers, classifies once for calls, parameters, results, and `va_list`. Classifying in the lowering (an HFA as its floats, a small struct as `i64` words) can't express AAPCS64's grouping in a flat scalar signature: an HFA or a two-word struct that doesn't fit goes to the stack whole and closes its registers, and an HFA on the stack is packed. Pointers to caller copies in MFIR (LLVM's `byval`) would add a signature marker and copies on every call for no native difference. Values rather than bytes keep the HFIR semantics of aggregate calls and every value proof as they were. The ABI torture test (`tests/abi.rs`: random signatures, `struct<auto>` and packed ones and reordered HFAs included, compiled by GCC and by FIR, each with and without `-O`, both directions, FIR to FIR, and through `...` (a non-C composite as its twin, the C composite of its layout and class), a third of them exhausting a register class and passing scalars after a composite on the stack, every pointer dereferenced where it arrives, FIR's calls also run in the interpreter as MFIR and LFIR, and split pointers checked to be refused) checks the agreement with C; it found GCC's zero-length-array rule for HFAs. Review found that classifying HFAs in declared order disagreed with C for a reordered `struct<auto>`, and that a packed pointer split across words lost its provenance (LFIR wasn't a refinement for a `read(args)` callee); refusing those composites is simpler than carrying pointer fragments through registers, and costs nothing for C, whose packed structs `fai-cc` rejects |
| Instruction selection | MFIR, or HFIR made only of core ops (`ptr.field`, `ptr.index` become offsets), to LFIR over virtual registers, op by op. Each SSA value gets a virtual register; region parameters and `cf.if`/`cf.loop`/`cf.blocks` results are registers written by parallel moves where control reaches them; `copy`, `freeze`, `trunc`, and the pointer/address casts reuse their operand's register. Integers use the low N bits; comparisons, division, right shifts, extensions, and overflow checks extend first (`sbfx`/`ubfx`). `.wrap`/`.nsw`/`.nuw`/`.ub` compute the wrapped result; `.trap` branches to a trap block (flags at 32 and 64 bits, exact 64-bit results below, `smulh`/`umulh` for products); `.sat` selects the bound. Division traps on zero or `MIN / -1` when asked, otherwise relies on `sdiv`/`udiv` giving 0 and `msub`-style remainders giving `x`. Shifts of at least the width trap, mask (`and`, or a remainder for widths that aren't powers of two), or select the shifted-out value. `cf.switch` is a binary search over sorted keys. Loads and stores split odd sizes; `mem.copy` copies up to 64 bytes through registers and larger sizes in a loop whose direction follows the addresses. `mem.alloc`/`mem.free` call the allocator (`malloc`, or `aligned_alloc` above 16-byte alignment, and `free`, for every family). `cf.check.R` tests bit 0 and branches to a trap block with reason `R`; `poison` of any scalar type is 0. Floats live in FP registers, an `f32` in the low 32 bits: `fadd`…`fdiv`, `fneg`, `fabs`, `fsqrt`; `float.fma` copies its addend into the destination and `fmadd`s; `copysign` masks the bits in general-purpose registers; `float.cmp.P` is `fcmp` and `cset` of one condition (`oeq` eq, `olt` mi, `ole` ls, `ogt` gt, `oge` ge, `ord` vc, `uno` vs, `une` ne, `ult` lt, `ule` le, `ugt` hi, `uge` hs) or, for `ueq` and `one`, a `cset` and a `csinc`; `ext`/`trunc` are `fcvt`; `int.to_float` extends to 64 bits and `scvtf`/`ucvtf`s; `float.to_int` `fcvtz`s at 64 bits (saturating, NaN 0), then clamps for `.sat` below 64 bits, and for `.trap` first traps (reason `convert`) on NaN (`fcmp x, x`) and outside exactly representable bounds (`x > lo - 1`, or `x ≥ lo` where `lo - 1` doesn't fit the format, and `x < hi + 1`); `from_bits`, `to_bits`, `poison` (from `xzr`), and constants are `fmov` (an 8-bit immediate when one encodes the value, else through a general-purpose register); `select` is `fcsel`. Integers wider than 64 bits are held as their low 64 bits through the ops whose low 64 result bits depend only on their operands' (constants, `copy`, `freeze`, `select`, bitwise ops, non-trapping, non-saturating `add`/`sub`/`mul`, extensions to them, truncations from them), which covers the lowering of `ptr.index.inbounds` (an exact product at twice the address size, truncated with `.nsw`, `poison` where it doesn't fit); anywhere else they are errors, as are holes, non-64-bit memory spaces, and HFIR's building blocks (lower first: AOT driver). `exn.throw` sets the exception slot and branches to the epilogue; a call to a function that may throw is followed by `aarch64.b.exn` to the epilogue (a plain call) or to a block that takes the exception and jumps to the handler (`func.invoke`). Blocks are laid out in source order, traps and landing blocks last. A call of a variadic function, a variadic function's register save areas, `va.start`, and `va.arg` are as decision Varargs says; `va.end` is nothing. A struct or array value is its leaves' registers (`agg.*` and `copy` regroup them), packed into words (shifts and `orr`, a pointer filling a word moved as it is) or moved to FP registers where it travels, stored to the stack, to a copy in the frame passed by address, or at `x8`, and unpacked where it arrives (decision: C ABI for aggregates); any other op on one is a compile error | Each op's edge cases come from its modifiers alone, so the selection is a table of local rules a later checker can match against the ASL semantics. Poison and UB allow any value, which is what makes the wrapped result correct for them, and the low bits of a wide value whose truncation would be `poison` |
| Register allocation | Linear scan over hull intervals (no lifetime holes) from a postorder liveness dataflow, in two classes: a virtual register takes a physical one of its own class (`vN` an `x`, `fvN` a `d`; isel numbers both from one counter). Physical registers the code names get exact segments that a virtual register's interval may not overlap, which keeps values live across calls in callee-saved registers (`x19`…`x28`, `d8`…`d15`); calls clobber AAPCS64's caller-saved ones (`x0`…`x18`, `x30`, `d0`…`d7`, `d16`…`d31`). No free register: the active interval of the class ending last is spilled if its register suits and it ends later, else the new one. Spilled registers live in 8-byte slots, loaded into `x15`/`x17` (`d29`…`d31` for FP, never allocated: `fmadd` reads three) before each read and stored after each write (`x16` for far slot addresses). The frame saves the callee-saved registers the allocation used, the FP ones' low 64 bits after the general-purpose ones. The certificate is the assignment (each virtual register's physical register or slot) with the code before allocation; its check first requires each virtual register the code names to have a home it may have (a register of its own class from the allocatable sets, so never `x15`…`x18`, `x29`, `x30`, `sp`, `xzr`, or `d29`…`d31`, or a slot below the slot count that no other virtual register has), then is a forward dataflow of which virtual register each physical one of either class holds (writes, call clobbers, writes of physical registers by name), met by intersection at joins, requiring every read to find its value. Debug builds run the check on every function. Varargs needed no change: a variadic function's register save areas are frame slots that the entry stores from the argument registers, which name them like any physical register (decision: Varargs) | The simplest allocator that handles calls and pressure; a validator in the style of CompCert's (Rideau and Leroy) needs only the assignment, and its Lean proof is the trust round's |
| Traps at run time | `aarch64.trap.R` calls `__fir_trap(reason, line, col)`: reasons `div0` 0, `overflow` 1, `shift` 2, `oom` 3, `bounds` 4, `tag` 5, `convert` 6; `0xffffffff` for no location. Each object defines a weak `__fir_trap` that executes `brk #1000`; programs and the test harness define their own | Precise: all earlier effects are done, and the reason and location reach the handler, so a runtime can raise the language's exception and the tests can print `fir run`'s line |
| AOT driver | `fir compile FILE [-O] [-o OUT] [--emit mfir\|asm\|lfir\|lfir-vregs] [--os linux\|darwin]`: verify; lower HFIR to MFIR (`fir lower`) and, with `-O`, run the default pass pipeline (`fir opt -O`), both through `fir::backend::prepare`; select, allocate (functions in parallel), then emit GNU assembly (ELF, or Mach-O with `_` symbols, `@PAGE` relocations, and `__DATA,__const` for constant data with addresses). `-o x.s` writes assembly; otherwise `$FIR_CC` (or `cc` on AArch64, `aarch64-unknown-linux-gnu-cc` elsewhere) assembles and links | The system assembler and linker already handle relocations, PLT and GOT, and both object formats; FIR's own object writer can come with the binary format. Lowering in the driver makes HFIR, what frontends build, compile directly |
| Backend testing | `crates/fir/tests/aarch64.rs` compiles every fixture with `// run:` lines (an escaping exception is pending in the harness's `__fir_exn`, and `main` prints `threw ptr …`) (each with only the functions its runs reach; runs the backend can't compile are counted) and random programs (the fuzzer's narrow mode: integers up to 64 bits, overflow ops whose lowering stays within 64 bits, the default layout, and HFIR's building blocks) as `fir compile` does, lowering HFIR first, with a generated C `main` and extern stubs that print `fir run`'s line, runs them (natively on AArch64, `qemu-aarch64` elsewhere; the dev shell adds a cross GCC and qemu-user on x86-64 Linux), and runs their LFIR before and after allocation in the interpreter, and as text in `fir-ref` (which must print what `fir run` prints). Floats pass as C's `float` and `double` and print as their bits, which the test renders as `fir run` does; the reference picks NaNs by Arm's rule (`fir::interp::run_detail_with`, `NanRule::Arm`, the executable twin of `Oracle.arm`), so a native NaN must equal that oracle's, payload and sign included, and the narrow mode generates floats. A variadic external function's arguments are its parameters' types, then variadic ones (`argsFit`); the event shows them all | Exposure is required: a C callee may cast any pointer it holds to an integer (PNVI-ae), and a semantics that missed it would report UB that doesn't exist. The world sees the memory it may read, so a store a callee reads is never dead. Halting steps add no events, so a halted run's trace is its last state's; the UB after a violated fact stays after the event, so a call with a fact can't be deleted. A callee's writes aren't recorded in `noalias` scopes (fewer UBs, so sound); callbacks into the module aren't modeled yet (open item 1) |
| Trace refinement | Target trace `t` refines source trace `s` when their events match one for one (same callee, arguments refining the source's, so any value where the source passed `poison`, the same results) and the endings refine as before (`threw v` refines `threw v'` when `v` refines `v'`); or `s` is UB or stuck after events `es`, and `t` starts with events refining `es`, then does anything (finite or infinite). An infinite trace refines an infinite one event by event, or a source that is UB after a prefix of it; it never refines a finite non-UB trace, and a finite trace never refines an infinite one. A function refines another when, in every *monotone* world (one that may answer a refined call or history whatever it may answer the source's), each target behavior refines a source behavior; the oracle stays existential per side, the world is shared. Refinement is a preorder except at `ambiguous` endings (`Behavior.Refines.refl`/`trans`) | UB is not time travel past observable events: the source performed its events before its UB, so the target must perform them too, but nothing after (C11 5.1.2.3p6 observes I/O; LLVM and CompCert use the same prefix rule). Sharing the world, which answers from what the callee may read, makes memory a callee reads observable without putting it in the trace; quantifying over all worlds is CompCert's "for all external call semantics", and monotonicity is what makes refining `poison` arguments sound, since the real world never sees `poison` |

Related states must have traces that match event by event, and a source escapes into UB only after events the target has already matched, so the theorem proves trace refinement, finite or infinite. Core computations can't see the environment, so no proof needs an invariant about it | Rewrite proofs stay about one step; the same approach will carry type safety |

0. FIR-1 program-level proofs: the simulation framework, dead store elimination, store-to-load forwarding, copy propagation through straight-line code (the ops after a copy in its block, up to the first region or call), and dead code elimination (deleting copies, constants, and `poison` that no later op in their region reads, at any depth, across calls) are proved, as is the HFIR lowering's expansion pass (checked arithmetic, `ptr.field`, `ptr.index`). Next for the lowering: scalarizing and lowering `cf.try` (decision: Lowering proofs; the latter needs a simulation between stacks of different shapes: a `cf.try` frame against a `cf.blocks` frame, call frames with and without handlers), and then the whole lowering of a module, whose functions call each other's lowerings (a refinement between two modules). Next: copy propagation into regions and across calls (needs a code relation that substitutes operands, with `%x` and `%y` agreeing in every frame that runs substituted code, and frames below a call related by the proof's own relation), mem2reg (also needs a relation between memories, and hidden names that rewritten target code reads), dead allocations, and reordering across `noalias`. Also: the angelic choice for ambiguous addresses, replacing the `ambiguous` outcome; type safety (verified programs never get stuck)
1. Structure details: symbol visibility and linkage, external globals; for external functions: callbacks into the module (passing a function pointer to `qsort` today lets the world call nothing), recording a callee's writes in `noalias` scopes, a `nocapture`-like effect so passing a pointer needn't expose it, facts on parameters and results of declarations, and volatile events; named (and recursive) types so large structs aren't repeated, initializers that point inside a global (`&a[3]` needs a field and index path, not byte offsets), graph (unordered) regions for dataflow hardware
2. Control flow details: coroutines, async, and generators (an HFIR building block lowered to a state machine; decided in the building-blocks round)
3. Types details: closure types; unions in memory (a tag size and layout, niches); dynamic indices into array values; `f16` and `bf16`
4. ABI: C calling conventions, owned by FIR. AAPCS64 for integers, pointers, and floats is decided (Calling convention); variadic functions are decided for Linux (Varargs); structs and arrays by value are decided for Linux (C ABI for aggregates: HFAs, composites up to 16 bytes in registers, larger ones by reference, results through `x8`); next: `i128` in register pairs (and composites with integer leaves wider than 64 bits, which the backend rejects), and macOS's variant (packed stack arguments, composites on the stack included, extended narrow arguments, variadic arguments all on the stack with a `char *` `va_list`, which `va_list`'s layout in the memory space allows), and other targets' classifications (x86-64's SysV eightbytes) behind the same MFIR
5. Representations: ops are declared once and the parsers, printers, typing rules, and Rust `OpKind`, and builder methods (Rust and C) come from the declarations (see Op syntax; the Rust implementation is checked against `fir-ref fmt --unverified` and `fir-ref check` on every test file: same output, or the same error; the Rust interpreter, `fir run`, is checked against `fir-ref run` on every `// run:` line and on random well-typed programs, for the oracle that always answers 0 and the world that answers every external call with zeros). Layers and dialects are declared per op and enforced (decisions: Layers, Dialects). Next: generic ops whose names `OpKind` doesn't know, for dialects (the generic form parses only known ops for now); naming the target in MFIR, so that the target legality rule can admit a target's ops there (`layer mfir` names none yet, and no op is in MFIR and a target's dialect); using the declared effects and trust tiers, which nothing reads yet; Rust limits that Lean doesn't have (sizes and array lengths are 64-bit; alignments, widths, field indices, memory-space sizes, and locations 32-bit; `fir run` takes address sizes up to 64 bits); binary format; versioning
6. Transformations: the pass manager and the four proved rewrites as passes exist (decision: Passes; `crates/fir/src/passes/`), checked by differential testing against the original program on every fixture and on random programs. Next: matching each pass to its proof by construction; proving that rewrites compose (intermediate programs stay `Decided`, and refining a callee refines its callers, so a whole module can be optimized); proving `Pure` for the ops `dce` deletes beyond copies, constants, and `poison`; copy propagation into regions and across calls once proved (item 0); analyses, a rule DSL, incremental compilation; the proved restructuring of `cf.blocks` into `cf.if` and `cf.loop` (decision: Control flow)
7. Lowering: target description format, ISA semantics sources (AArch64's from Arm's ASL), debug info. AArch64 isel and register allocation are decided (Instruction selection, Register allocation); next: the allocator's Lean-proved checker, isel rules checked against the ASL semantics, coalescing and lifetime holes, folding offsets and shifted operands, jump tables, `madd`/`ldp`/`stp` and a four-register `fmadd` (a wider `OpKind` or side tables; `fmadd`'s accumulator form costs an `fmov`), a proof that instruction selection and allocation refine their source (the FP instructions' NaN results are already proved allowed), native unwind tables for exceptions (DWARF CFI and an LSDA with a small personality routine, replacing the error-return convention of Exceptions at run time, so C++ frames can be unwound through), a thread-local exception slot (TLS relocations, Mach-O's thread-local variables), and guaranteed tail calls (`func.call.tail`)
8. AOT driver: `fir compile` is decided (AOT driver), with HFIR lowering and the optional `-O` pipeline in front of isel; next: an object file writer, integers wider than 64 bits beyond their low bits (the lowering checks `int.*.overflow` on `i64` at 65 bits, and `mul` above 32 bits at twice the bits), and a runtime library (traps that raise language exceptions)
