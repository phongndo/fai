# Decision log

## Decided

| Area | Decision | Rationale |
|---|---|---|
| Architecture | The Lean 4 spec is the source of truth; the production compiler is in Rust, with a self-hosted implementation as the long-term goal | Proofs need a precise reference; the spec outlives any one implementation language. Rust is chosen for correctness first: memory safety and data-race freedom rule out whole bug classes in the compiler itself, and exhaustive `match` on op kinds catches missing cases at compile time |
| North star | Semantics as the platform | See [00-north-star.md](00-north-star.md) |
| Scope | General-purpose target. The first phase is the AOT compiler only, with a C subset as the first frontend. JIT, VM embedding, and web (Wasm) are later phases; see [Phasing](00-north-star.md#phasing) | One execution mode keeps the first phase small, and the core is designed so later phases don't change it. C has the hardest well-understood UB and large existing test corpora |
| Layers | HFIR / MFIR / LFIR as fixed contracts, with the target legality rule. Each op's declaration lists the layers that allow it (`layers hfir mfir`, the default). A module states its layer (`layer hfir`, `layer mfir`, `layer lfir aarch64`; HFIR when absent, and printed only when not HFIR), and the verifier rejects an op outside it before any other check. Today's core ops are in HFIR and MFIR, except `ptr.field` and `ptr.index` (HFIR only); LFIR for a target allows the target's dialect and, of the core ops, only `func.ret` | See [01-layers.md](01-layers.md). Declaring layers with the op keeps both verifiers enforcing the same contract. HFIR as the default keeps existing and hand-written modules valid. MFIR addresses by offsets (decision: Layout), and functions need `func.ret` in every layer |
| Extensibility | Dialect-ready from day one: generic op representation, three trust tiers per op; dialects are declared op groups for now (see Dialects) | Retrofitting generic ops is costly |
| Next round | Build HFIR, MFIR, and LFIR as layers down to AArch64 assembly, behind a builder API, before any frontend; see [03-plan.md](03-plan.md) | A compiler needs a stable platform to target; the C frontend then becomes the first compiler built on it |
| First target | AArch64. Its instruction semantics come from Arm's machine-readable ASL (via the Sail model) in the trust round; this round writes them by hand | An official spec instead of a transcription; native on Apple hardware, `qemu-aarch64` on Linux |
| LFIR for AArch64 | Machine form: `aarch64.*` ops (layers `lfir`) name their registers as immediates (`x0`…`x30`, `sp`, `xzr`, and virtual registers `v0`, `v1`, … before allocation; a new op-table field type `Reg`, a `u32` in Rust) and have no operands or results; the size (`.w`/`.x`, ASL's `sf`), condition codes, and operations are modifiers in the name. A function's body is `aarch64.code { ^b0: … }`: labeled blocks without parameters, each ending in `aarch64.b`, `aarch64.b.<cond> ^t, ^f`, `aarch64.ret`, or `aarch64.trap.<reason>`, with no fall-through. LFIR keeps `func.ret` only for a body that returns its parameters; `cf.blocks` stays out. The ops: three-register ALU (incl. `adds`/`subs`/`ands`, shifts by register, `mul`, `sdiv`/`udiv`, `smulh`/`umulh`), ALU with an immediate, shifts by an immediate, `sbfx`/`ubfx` from bit 0, `mov`, `movz`/`movn`/`movk`, `csel`/`csinc`/`csinv`/`csneg`, `ldr`/`str` of 1, 2, 4, 8 bytes at base plus offset, `adrl` (global or function address: `adrp`+`add`, or a GOT load for an external function), `bl`, `blr` (with the callee's signature), and runtime calls `bl.alloc`/`bl.free`. Which immediates encode is the emitter's concern, not the semantics' | SSA values can't name the physical registers that calling conventions, prologues, and spill code need; registers as immediates give one form before and after allocation, which both interpreters run, and the ASL describes instructions the same way (registers as fields of the encoding). Explicit blocks are what the hardware does; four-register ops (`madd`, `ldp`) are left out so `OpKind` stays 16 bytes |
| AArch64 semantics | `Fir.AArch64` gives each instruction's bits in ASL's shape (`AddWithCarry`, `ConditionHolds`, the `sf` size), to be replaced by an import of Arm's ASL. `Fir.AArch64Machine` runs LFIR over FIR's core (memory, allocations, events, oracle): registers hold *words*, 64 bits or a pointer with its provenance. 64-bit `add`/`sub` of an integer, moves, `csel`, and 8-byte loads and stores of a pointer's eight fragments keep provenance; every other use reads the address (realizing it, as `ptr.addr`). Registers are never `poison`: uninitialized bytes and `poison` arguments read as oracle choices. Memory is flat: an integer address reaches the live allocation holding those bytes, exposed or not; lifetimes and bounds are checked, alignment and `noalias`/`readonly` scopes are not. The stack is one 1 MiB allocation with `sp` at its end. Virtual registers are per call; physical ones are global, and `ret` checks that `x19`…`x29` and `sp` are as on entry (stuck otherwise). `ret` returns to the caller whatever `x30` holds. `fir-ref run` and `fir run` run `layer lfir aarch64` modules on this machine; existing proofs are untouched | LFIR must be a refinement target for isel and register allocation, so it may only be more defined than MFIR: hardware has no `poison` and no provenance checks on integer addresses. Keeping provenance where it is cheap keeps pointer results and events printable like MFIR's. A separate machine, not new frame kinds in `Fir.Interp`, leaves every simulation proof as it is |
| Calling convention | AAPCS64 for integers, pointers, and `bN` up to 64 bits: arguments in `x0`…`x7`, then 8-byte stack slots from `sp`; one or two results in `x0`, `x1`; three or more in 8-byte slots at the address the caller passes in `x8` (C's rule for a struct of 64-bit fields larger than 16 bytes). A narrow integer is in the low bits of its register, the rest unspecified. Callee-saved `x19`…`x28`, `x29` (frame pointer, always set up), `sp`; `x18` is never used. Frame: `x29` points at the saved `x29`/`x30` pair; below it the callee-saved registers, spill slots, locals (`mem.stack` slots, results areas), and the outgoing argument area at `sp`; `sp` is realigned when a local needs more than 16 bytes. Wider integers are rejected (`i128` would need register pairs); macOS's differences (stack arguments packed by size, callers extending narrow arguments) aren't handled yet | Matches C for every signature of 64-bit scalars, so C calls FIR and back; narrow results packing like C structs (two `i32` in `x0`) would cost shifts on every multi-result return for no client yet |
| Instruction selection | MFIR, or HFIR made only of core ops (`ptr.field`, `ptr.index` become offsets), to LFIR over virtual registers, op by op. Each SSA value gets a virtual register; region parameters and `cf.if`/`cf.loop`/`cf.blocks` results are registers written by parallel moves where control reaches them; `copy`, `freeze`, `trunc`, and the pointer/address casts reuse their operand's register. Integers use the low N bits; comparisons, division, right shifts, extensions, and overflow checks extend first (`sbfx`/`ubfx`). `.wrap`/`.nsw`/`.nuw`/`.ub` compute the wrapped result; `.trap` branches to a trap block (flags at 32 and 64 bits, exact 64-bit results below, `smulh`/`umulh` for products); `.sat` selects the bound. Division traps on zero or `MIN / -1` when asked, otherwise relies on `sdiv`/`udiv` giving 0 and `msub`-style remainders giving `x`. Shifts of at least the width trap, mask (`and`, or a remainder for widths that aren't powers of two), or select the shifted-out value. `cf.switch` is a binary search over sorted keys. Loads and stores split odd sizes; `mem.copy` copies up to 64 bytes through registers and larger sizes in a loop whose direction follows the addresses. `mem.alloc`/`mem.free` call the allocator (`malloc`, or `aligned_alloc` above 16-byte alignment, and `free`, for every family). Blocks are laid out in source order, traps last. Holes, wider integers, and non-64-bit memory spaces are errors | Each op's edge cases come from its modifiers alone, so the selection is a table of local rules a later checker can match against the ASL semantics. Poison and UB allow any value, which is what makes the wrapped result correct for them |
| Register allocation | Linear scan over hull intervals (no lifetime holes) from a postorder liveness dataflow; physical registers the code names get exact segments that a virtual register's interval may not overlap, which keeps values live across calls in callee-saved registers. No free register: the active interval ending last is spilled if its register suits and it ends later, else the new one. Spilled registers live in 8-byte slots, loaded into `x15`/`x17` before each read and stored after each write (`x16` for far slot addresses). The certificate is the assignment (each virtual register's physical register or slot) with the code before allocation; its check is a forward dataflow of which virtual register each physical one holds (writes, call clobbers, writes of physical registers by name), met by intersection at joins, requiring every read to find its value. Debug builds run the check on every function | The simplest allocator that handles calls and pressure; a validator in the style of CompCert's (Rideau and Leroy) needs only the assignment, and its Lean proof is the trust round's |
| Traps at run time | `aarch64.trap.R` calls `__fir_trap(reason, line, col)`: reasons `div0` 0, `overflow` 1, `shift` 2, `oom` 3; `0xffffffff` for no location. Each object defines a weak `__fir_trap` that executes `brk #1000`; programs and the test harness define their own | Precise: all earlier effects are done, and the reason and location reach the handler, so a runtime can raise the language's exception and the tests can print `fir run`'s line |
| AOT driver | `fir compile FILE [-o OUT] [--emit asm\|lfir\|lfir-vregs] [--os linux\|darwin]`: verify, select, allocate (functions in parallel), then emit GNU assembly (ELF, or Mach-O with `_` symbols, `@PAGE` relocations, and `__DATA,__const` for constant data with addresses). `-o x.s` writes assembly; otherwise `$FIR_CC` (or `cc` on AArch64, `aarch64-unknown-linux-gnu-cc` elsewhere) assembles and links | The system assembler and linker already handle relocations, PLT and GOT, and both object formats; FIR's own object writer can come with the binary format |
| Backend testing | `crates/fir/tests/aarch64.rs` compiles every fixture with `// run:` lines and random programs (the fuzzer's narrow mode: integers up to 64 bits, the default layout) with a generated C `main` and extern stubs that print `fir run`'s line, runs them (natively on AArch64, `qemu-aarch64` elsewhere; the dev shell adds a cross GCC and qemu-user on x86-64 Linux), and runs their LFIR before and after allocation in the interpreter, and as text in `fir-ref` (which must print what `fir run` prints). A run that ends in UB, gets stuck, reaches a hole, is ambiguous, or runs out of fuel isn't comparable; `poison` matches any value and non-null pointers print as `ptr ?`; leak notes are dropped; where a module observes addresses (`ptr.addr`, `ptr.expose`, pointer comparisons, integer reads of pointer bytes), a difference only in integers is counted, not failed | UB allows any behavior and addresses are the oracle's choice; everything else must match exactly, traps with their locations and events in order |
| C frontend | Clang parses and type-checks C; a LibTooling frontend lowers Clang's AST to HFIR through the C API. The first C round includes `float`/`double` and full varargs (defining variadic functions too) | Real C (preprocessor, headers, types) works from the start, FIR owns semantics from HFIR down, and the frontend exercises the C API |
| Dialects | Declared op groups in the op table (`aarch64.*`, building blocks), closed and versioned; opening the op set (unknown generic ops, the opaque tier) comes after the current round. An op's dialect is its name's namespace (`int`, `mem`, `ptr`, `cf`, `func`, `ty`), or `value` for the unprefixed `poison`, `freeze`, `copy`, and `select`. The LFIR targets are listed in `Fir.targets` (`aarch64`); an unknown target is a parse error | LFIR needs target dialects now; run-time registration can wait until something needs it. The namespace already groups ops, so the dialect needs no separate name |
| Builder API | Generated from the op table (`lake exe gen-builder`): one `FuncBuilder` method per op (`int_arith`, `mem_load`, `cf_cond_br`) and one C function over it (`fir_int_arith`), taking the result types the op's rule doesn't imply, every modifier (none has a default), then the immediates and operands in the order the text writes them. Ops with regions have a `_begin` form and a closure form; the blocks of `cf.blocks` are made one by one and given to their op at the end. `ModuleBuilder` declares the memory space, struct, array, and function types (one table per module, copied into a function's table the first time it uses one), functions (declared before they are called), external functions, and globals; one function is built at a time, written straight into a reused `Body`. Building checks what is cheap (operand counts and types by the op's rule, implied result types, alignments, extensions, calls against signatures, ids that exist) and leaves scoping, terminators, labels, and layout to the verifier. Values are named on request; the others get their ids as names. Every verified test file and fuzzer program, and the AArch64 backend's LFIR of them, is rebuilt through it and prints byte for byte as parsed. The module's layer is set with `set_layer` (`fir_module_set_layer`), and each op is checked against it as it is built, with the verifier's message. The `aarch64.*` ops take registers as `Reg` (in C a `FirReg`: `x0`…`x30` are 0…30, `sp` 31, `xzr` 32, `vN` 64 + N), checked as they are built, and `aarch64.code` gets its blocks as `cf.blocks` does | One source of truth for ops; a frontend can't forget an edge case, because a missing modifier doesn't compile. Cheap checks catch frontend bugs where they happen, while the verifier stays the one authority. Building a module is about 2.4 times as fast as parsing its text |
| Deferred UB | `poison` plus `freeze`; no `undef`; branching on poison is UB | Lessons from LLVM's PLDI'17 work and the byte-type RFC |
| Integers | Signless `iN`; signedness lives in ops (`div.s`, `div.u`); mandatory UB modifiers (`.wrap`, `.nsw`, `.nuw`, `.trap`, `.sat`) with no default; optional value facts tagged `assume`, `check`, or `proved` | Maps one-to-one to Lean's `BitVec`; no hidden semantics; one way for frontends to pass knowledge to the optimizer |
| Types in text | Written on every result (`%r: i32 = ...`). Structs, arrays, and function types are written out where used: `struct<C>{i32, ptr}`, `array<4 x i32>`, `func<(i32, ptr) -> i32>` | Each line can be read and checked on its own |
| API | Stable C API from day one, exported from Rust (`crates/fir-capi`: `extern "C"`, header `include/fir.h` generated by cbindgen, which a test keeps current). Modules and the function being built are opaque handles (`FirModule`, `FirBuilder`); everything else is a 32-bit id, and modifiers are fixed integer constants. A failed call returns `FIR_INVALID` or a status, changes nothing, and leaves a message on the module; no panic crosses the boundary. The caller frees modules, builders, and returned strings; pointers passed in are only read during the call. Versioned by `FIR_API_VERSION` (major and minor): a release only adds, and a removal or change bumps the major version; op functions follow the op table, versioned the same way. A C test program built with clang runs in `cargo test` | Frontends in any language; replaceable implementation. Ids and integer constants keep the ABI plain C, and ids and enum values from C are checked, not trusted |
| Structure | Everything is an op: modules, functions, and target modules are ops with regions; typed Rust wrappers sit over the generic op | One grammar, verifier, and Lean notion of op; dialects add containers (for example GPU modules nested in a host module) without special cases |
| Storage | Data-oriented by default: a per-function arena of flat arrays, with ops, regions, values, strings, integers, and holes referenced by 32-bit index; ordering uses index-based linked lists. Op kinds, operands, and facts are small `Copy` values that own no heap memory; what varies in size lives once in a side table. Fields read separately are separate columns (an op's kind, its lists, its links, its location); fields always used together stay together, to keep allocations per function few. Builders reuse their arrays and copy each finished function out exactly sized. Use lists are an index passes build on demand (a head per value, a next link per operand slot), which every edit then keeps exact; parsing doesn't pay for them | Cache-friendly; stable op IDs for free; cheap snapshots for translation validation; near-free serialization (MFIR bytecode); matches the Lean model; functions compile in parallel |
| Provenance | Source locations on every op, always. Derivation chains (rule, source ops) are configurable: on in development builds, optional in release builds | Powers `--explain`, miscompile bisection, and UB-exploitation reports, with a choice of memory cost |
| Control flow | Structured regions (`cf.if`, `cf.loop`) by default in HFIR and MFIR. Jumps are allowed only inside an explicit `cf.blocks` region (for C `goto` and `switch` fall-through). A proved restructuring pass converts `cf.blocks` for Wasm and GPU targets; irreducible control flow is rejected for GPUs. LFIR uses the target's form | Easy proofs and direct Wasm/GPU output, while C stays fully supported and jumps stay visible where used |
| Value merging | Block arguments (`cf.br ^join(%n)` → `^join(%r: i32)`), not φ nodes | Matches structured `yield`; already modeled by lean-mlir and VeIR |
| Forward progress | A per-loop semantic attribute: `cf.loop progress` may assume a side-effect-free loop terminates; plain `cf.loop` assumes nothing (the default) | C and C++ keep their optimizations; Rust and Wasm stay correct (LLVM miscompiled Rust's `loop {}` before adding `mustprogress`); gives the infinite-loop tool a precise rule |
| Jumps | `cf.blocks [progress] { ^a: … ^b(%x: T): … }` holds labeled blocks and is entered at the first, which has no parameters. Its jumps are terminators: `cf.br ^b(%x)`, `cf.cond_br %c, ^t(…), ^f(…)`, and `cf.switch %v, default ^d(…), [1: ^a(…), …]`, which exists only here. They name blocks of the nearest enclosing `cf.blocks`, from its blocks or from `cf.if` and `cf.loop` regions nested in them. In a block, `cf.yield` leaves with the op's results; `cf.break`, `cf.continue`, and `func.ret` leave as anywhere else. Every block ends with a terminator: there is no fall-through | C's `goto` out of a loop needn't unstructure the loop; C's `switch` fall-through is a visible `cf.br` to the next case; nested `cf.blocks` stay independent. A structured switch adds nothing a `cf.blocks` doesn't express |
| Block scoping | A block is a region: a value defined in it is visible only there (and in regions nested in it), values from outside the `cf.blocks` in all its blocks, and block arguments carry everything else. Labels are unique in their `cf.blocks` and name only its blocks | No dominance analysis in the verifier or the semantics: a block's frame holds its arguments and its ops' results, as a loop iteration's does. Frontends thread values through block arguments, as mem2reg does for slots |
| Jump semantics | A `cf.blocks` frame stays on the stack while its current block runs above it. A jump pops the frames above it, ending their stack memory, and starts the target with only its arguments bound, as `cf.continue` starts an iteration; a back edge gets fresh stack memory. A jump on `poison` is UB. `cf.switch` keys fit the value's type, signed or unsigned, and differ modulo `2^N` | The model loops already have: the lockstep layer and the run invariants extend by one frame kind, and dead stores, forwarding, copy propagation, and dead code elimination are proved inside blocks with unchanged statements |
| Progress through jumps | `cf.blocks progress` may assume control leaves it, like `cf.loop progress`: a run that never leaves its frame (jumping forever, or stuck in a callee) is UB. Plain `cf.blocks` assumes nothing | C++ loops lowered to jumps keep their forward-progress assumption; C's `goto` loops, which have none, use plain `cf.blocks`. One definition for both: the frame is never left |
| Branch targets | An op kind holds each target as data: a label and an argument count (`Succ`), and `cf.switch`'s cases as a list; the arguments are among the op's operands, after its own. Labels live on regions. The generic form writes a target as `^b(2)` and a labeled region as `^b(%x: T) { … }`. In Rust, targets and case lists are ids into side tables, so `OpKind` stays 16 bytes | Branches keep the op shape (kind, results, operands, regions): use lists, passes, and proofs see their arguments as operands, with no separate successor list. The generic form shows every op exactly |
| Exceptions | Layered. HFIR has a structured `cf.try { } catch %e { }` building block. In MFIR, every call that may throw names its handler. LFIR lowers to native unwind tables or Wasm exception handling | One proved lowering for every language with exceptions; every path is visible to the optimizer |
| Floats | Core types `f16`, `bf16`, `f32`, `f64`; other formats (such as fp8) through dialects. Behavior is decided in the op-semantics round | Covers mainstream CPU, GPU, and ML formats without bloating the core |
| Vectors | Fixed (`vec<4 x f32>`) and scalable (`vec<[4] x f32>`) vectors, both in the core | All CPU SIMD: AVX, NEON, Wasm SIMD, ARM SVE, RISC-V V. LLVM added scalable vectors late and painfully |
| Pointers | Opaque `ptr`, with named memory spaces (`ptr<gpu.shared>`, `ptr<wasm.mem1>`); load and store ops carry the accessed type | Readable, no needless casts. LLVM spent years removing typed pointers, and its numbered address spaces are unreadable |
| Layout | FIR owns struct layout through policies: `struct<C>` (platform C layout per target), `struct<packed>`, `struct<auto>` (FIR may reorder fields). HFIR accesses fields by index; MFIR computes offsets (`ptr.field` and `ptr.index` are HFIR only) | Frontends never do per-platform layout arithmetic; prepares for FIR owning the C ABI |
| Aggregates | Structs and arrays shape stack slots (`mem.stack.of T, align N`, aligned to the larger of N and T's alignment) and globals, address computation (`ptr.field`, `ptr.index`), copies (`mem.copy T %dst, %src, align N`), and constants (`ty.size`, `ty.align`, `ty.offset`). Outside HFIR they are memory types only: values stay `iN`, `ptr`, and `bN`, and the verifier rejects aggregate and function types on results, parameters, and holes; HFIR also has them as values (decision: Aggregate values). `mem.copy` moves the bytes exactly as a `bN` load and store would (padding's `poison` and pointer fragments included), and overlapping copies are defined | C needs aggregates in memory, not in registers: struct assignment is a byte copy, and by-value arguments belong to the C ABI (open item 4). SSA aggregates need `insert`/`extract` and padding rules, and every value proof (forwarding's decode-of-encode, mem2reg) would grow cases; LLVM's first-class aggregate loads and stores are a known source of poor code. Adding them later changes none of these ops |
| Struct layout | `struct<C>`: each field at the next multiple of its alignment, in order; the struct aligns to its largest field (1 if empty) and its size is the end rounded up to that. `struct<packed>`: no padding, alignment 1. `struct<auto>`: the C rule after a stable sort by decreasing alignment; FIR may change this rule, so only `ptr.field` and `ty.offset` say where fields are. A field or element takes its type's size rounded up to its alignment (`i24` takes 4 bytes in a struct, 3 in a load); `array<N x T>` is N of them, aligned like T. A struct's or array's size must be below 2^address size | The System V and AAPCS64 C rules, and LLVM's struct layout; `auto` is Rust's default rule (least padding); the size limit makes every offset an address-size integer |
| Data layout | Each memory space also declares a pointer alignment (default: the largest power of two not above the pointer size in bytes) and an integer alignment table (default `8:1 16:2 32:4 64:8 128:16`, x86-64 System V): `memspace default ptr 32 addr 32 align 4 int 8:1 16:2 32:4 64:4`, printed only where not the default. `iN` and `bN` align like the smallest listed width at least N, else the largest listed (LLVM's rule). Full target descriptions come with the targets (open item 7) | Enough for C layout on the common 32- and 64-bit ABIs (i386 is one entry, `64:4`). It lives in the memory space, which no step changes (`Fir.Space`), so layout facts hold for whole runs |
| Address computation | `ptr.field.inbounds T %p, i` is `ptr.offset.inbounds %p, offset(T, i)`; `ptr.index.inbounds T %p, %i` is `ptr.offset.inbounds %p, %i × stride(T)` with `%i` signed, and is also `poison` if the product doesn't fit a signed address (LLVM's `getelementptr inbounds nusw`). The `.wrap` forms wrap the product to the address size and never give `poison` themselves. A `poison` operand gives `poison`. Field indices are constants of a struct type, checked by the verifier | One in-bounds rule (In-bounds offsets) keeps alias analysis sound; field-by-index is the HFIR half of the Layout decision, and lowers to `ptr.offset` |
| Globals | `global [const] @g: T [align N] = INIT`, where INIT is `zero`, an integer, `null`, `@g` or `@f` (an address), `bytes "hex"` (the whole object), or `{…}` (one per field or element, padding zero). Before the call starts, each global becomes an allocation, numbered first in declaration order, aligned to the larger of N and T's alignment, never freed, with provenance and a lazily assigned address like any other; `mem.global @g` gives a pointer to it. Writing a `const` global is UB (`const-write`), checked as a `readonly` scope lasting the whole run, so it composes with `noalias` scopes; freeing a global is `bad-free`. Globals and functions share one namespace | C static storage, including zeroed padding (C11 6.7.9p10); constant data can live in read-only memory and be merged; one allocation model for every object, so the provenance, exposure, and address rules need no special cases |
| Function pointers | `func.addr @f` gives a pointer to `@f`'s function object: an allocation of size 0, made the first time something takes the address (functions an initializer names come right after the globals), so its numbering doesn't disturb code that never takes one. No load, store, or copy may touch it (`func-access`); its address is observed and exposed like any other. `func.call.indirect func<(T…) -> U…> %p(…)` calls through `%p`, and is UB (`bad-call`) unless `%p` resolves to the start of a function whose parameter and result types are exactly the signature's; facts aren't part of the signature. A null or provenance-free pointer is `no-provenance`, as for accesses. The function type `func<…>` is not a value type | What C needs (and later vtables and closures); a mismatched call is UB in C (C11 6.3.2.3p8) and a trap in Wasm's `call_indirect`, and naming it lets sanitizer mode check it. Size 0 makes every data access out of bounds by construction, and the explicit kind gives the precise reason |
| GC references | Deferred to a later `gc` dialect. **Constraint:** the core type system and memory model must allow non-integral types (values that are not plain bytes and cannot be cast to integers), so `gc.ref<T>` can be added without changing the core | Faster start. The constraint keeps the VM kit and WasmGC possible later |
| Edge-case vocabulary | Every op with an edge case must name its behavior from one fixed vocabulary: `.wrap`; `.nsw`/`.nuw` (poison); `.ub` (immediate UB, so the op can't be executed speculatively); `.trap`; `.sat`; `.mask`; `.total` (always defined, e.g. `x/0 = 0`). Examples: C's `/` is `int.div.s.ub`, Java's is `int.div.s.trap.wrap`; a wrong union variant is `union.get.ub` or `union.get.trap`, an index out of a slice `slice.get.ub` or `slice.get.trap` | No hidden defaults. Each language's rule is visible on the op, to people, agents, and tools |
| Float semantics | Strict IEEE 754 with round-to-nearest by default. Fast-math permissions are per-op modifiers (`.reassoc`, `.contract`, `.nnan`/`.ninf` meaning poison if violated, …). Other rounding modes are separate ops, never global state | Permissions are visible exactly where granted; avoids global `-ffast-math` surprises and LLVM's floating-point-environment problems |
| NaN determinism | NaN bit patterns are nondeterministic within an allowed set by default; a build can opt into a deterministic profile (canonical NaNs, and the same rule for other nondeterministic ops such as relaxed SIMD) | Each chip runs at its natural speed by default; bit-identical results are available for reproducibility, testing, and replay (as in Wasm 3.0) |
| Traps | Precise: a trap happens exactly at its op, with all earlier effects done and no later ones. Each trap carries a reason code (`bounds`, `div0`, `overflow`, …) | VMs can raise language exceptions at the right point; sanitizers report exactly; effect-free code can still move across traps |
| Effects | A fixed set of effect categories: `read`/`write` (each with an optional resource tag such as a memory space, `errno`, or a GC heap), `alloc`/`free`, `trap`, `diverge`, `unwind`, `sync`, `extern` | "Can A move past B?" becomes a small, provable table; tags keep precision |
| Effect soundness | Declared effects are checked against semantics for each trust tier: proved in Lean (verified), checked automatically (specified), conservatively `extern` (opaque) | Removes the "wrong effect declaration → silent miscompile" bug class, which MLIR and V8 are both exposed to |
| Call effects | Function effects are trust-tagged facts: `effects[read(args)] assume` for external functions, `effects[] proved` when FIR infers them from the body; spot-checkable in sanitizer mode | One mechanism for everything the optimizer relies on |
| External functions | `extern func @puts(ptr) -> i32 effects[read(args)] assume` declares a function outside the module, in the namespace of functions and globals; `func.call`, `func.addr`, and `func.call.indirect` reach it like any function (a function object of size 0, signature checked the same way). Its effects are mandatory and list what it may do; anything unlisted it doesn't: `read(M)`/`write(M)` for M = `args` (the allocations its pointer arguments point into, not memory reached through them: LLVM's `argmemonly`), `exposed` (every exposed allocation), or `globals`; `alloc`; `free`; `trap`/`diverge` (it may not return). Effects are `assume` or `check`, never `proved`. `unwind` is rejected until exceptions come. Parameters and results are value types without facts | What the C frontend needs for libc. No hidden defaults: a forgotten clause doesn't silently mean "anything". The classes are the ones LLVM's `memory(argmem: …, inaccessiblemem: …)` and C's linkage give a separately compiled callee |
| Events | A behavior is a trace: the events a run performs, then (if finitely many) how it ends: returned values, trap, UB, stuck, hole, `diverge` (runs forever with no further event), or `ambiguous`. A run with infinitely many events has no ending. Today the only event is a call to an external function, recording the callee, the arguments as passed (`poison` included), and the results the world returned, or `never` | The standard observable-behavior model (CompCert's traces): what the program does to the outside is exactly the calls it makes and what they returned. Results are inputs, recorded so a trace says which world answers it saw |
| External call semantics | Calling an external function is one step: check the arguments' types; compute what the callee can reach (its pointer arguments' (allocation, tag) pairs, the globals if an effect names `globals`, every exposed pair if one names `exposed`, then repeatedly the pointers stored in memory it may read) and expose all of it; show the *world* the callee, its result types, its arguments, and the bytes of every allocation it may read; take one oracle answer; and let the world answer, given the events so far. An answer returns results after writes, frees, and new allocations, or never returns. An answer the effects don't allow (wrong types; writes or frees outside memory it may write, `const` globals excluded; frees of non-heap memory or without `free`; new allocations without `alloc` or with used ids; pointers it can't reach; not returning without `trap` or `diverge`) is never given: the call returns zeros instead. The event is recorded at once; the results come back through a synthesized `func.ret` in a frame of their own, so the caller checks their types and facts as for any callee, one step later (a violated fact is UB after the event). A call that never returns replaces the stack with an empty loop: the run diverges silently, and no caller's `progress` loop is still running. `fir-ref run` and `fir run` use the world that answers zeros and changes nothing | Exposure is required: a C callee may cast any pointer it holds to an integer (PNVI-ae), and a semantics that missed it would report UB that doesn't exist. The world sees the memory it may read, so a store a callee reads is never dead. Halting steps add no events, so a halted run's trace is its last state's; the UB after a violated fact stays after the event, so a call with a fact can't be deleted. A callee's writes aren't recorded in `noalias` scopes (fewer UBs, so sound); callbacks into the module aren't modeled yet (open item 1) |
| Trace refinement | Target trace `t` refines source trace `s` when their events match one for one (same callee, arguments refining the source's, so any value where the source passed `poison`, the same results) and the endings refine as before; or `s` is UB or stuck after events `es`, and `t` starts with events refining `es`, then does anything (finite or infinite). An infinite trace refines an infinite one event by event, or a source that is UB after a prefix of it; it never refines a finite non-UB trace, and a finite trace never refines an infinite one. A function refines another when, in every *monotone* world (one that may answer a refined call or history whatever it may answer the source's), each target behavior refines a source behavior; the oracle stays existential per side, the world is shared. Refinement is a preorder except at `ambiguous` endings (`Behavior.Refines.refl`/`trans`) | UB is not time travel past observable events: the source performed its events before its UB, so the target must perform them too, but nothing after (C11 5.1.2.3p6 observes I/O; LLVM and CompCert use the same prefix rule). Sharing the world, which answers from what the callee may read, makes memory a callee reads observable without putting it in the trace; quantifying over all worlds is CompCert's "for all external call semantics", and monotonicity is what makes refining `poison` arguments sound, since the real world never sees `poison` |
| Verifier | Rules are defined once in Lean. The Rust verifier is generated from them where possible and differential-tested otherwise. Development builds verify after every pass; release builds verify at layer boundaries | Broken passes are caught immediately, by name; rules can't drift from the spec |
| Provenance | Pointers carry provenance (which allocation they belong to), following the exposed-provenance model of ISO C TS 6010 (PNVI-ae-udi). Explicit ops: `ptr.addr` (address only, exposes nothing), `ptr.expose` / `ptr.from_exposed` (C integer casts), `ptr.with_addr` (strict: same allocation, new address) | Alias analysis stays sound; C is fully supported; safe languages use the strict ops and keep full optimization; maps onto CHERI capability hardware. Avoids LLVM's integer-pointer cast miscompiles |
| Memory bytes | Each byte in memory is concrete bits, `poison` (uninitialized), or a fragment of a pointer with its provenance. A byte type (`b8`, `b32`, …) copies raw memory losslessly. Reading uninitialized memory as an integer yields poison | `memcpy` of pointers and padding is justified; uninitialized reads are precise for the tools. This is the role of LLVM's byte type, built in from the start |
| Allocation | First-class ops: `mem.stack` (freed at scope end), `mem.alloc` / `mem.free` tagged with an allocator family (`c.malloc`, `cpp.new`, custom), and globals | Cross-language allocation optimizations (removing dead allocations, moving heap allocations to the stack); catches mismatched and double frees; leak reports with source provenance |
| Aliasing | `noalias` is a trust-tagged fact on a pointer, scoped to a region: a function's body for its parameters, or an explicit scope op, which keeps the fact through inlining. Inside the scope, if a byte accessed through the pointer, or through any pointer derived from it by provenance, is written by anyone (freeing counts as a write), every access to that byte in the scope must go through derived pointers; otherwise UB. Reads may be shared freely. `readonly` also forbids writes through derived pointers (Rust `&T` is `[noalias, readonly]`). Provenance carries a derivation tag so "derived from" is exact, and `ptr.from_exposed` may pick any exposed tag. `check` mode inserts runtime checks (a `restrict` sanitizer). Type-based aliasing (C strict aliasing) is an opt-in fact, off by default | Checked against C `restrict` (C11 6.7.3.1: only modified objects count; provenance makes "based on" exact) and Rust's Tree Borrows (PLDI 2025: the fact corresponds to a protected function argument, and the protected states give these rules, including UB for a foreign read followed by a write through the reference). Replaces the earlier pairwise `noalias(%x)` form, which neither language needs. One checkable mechanism instead of LLVM's three trusted ones; strict aliasing is notoriously subtle (smtgcc can't model it; the Linux kernel disables it) |
| Concurrency | Based on the C++20 memory model (RC11): atomic orderings `relaxed`/`acquire`/`release`/`acq_rel`/`seq_cst`, and races on plain accesses are UB. Extensions: `unordered` racy-but-defined accesses (a racy read returns some written value) for Java, JS, and Wasm threads; scoped atomics (`workgroup`/`device`/`system`) following the GPU memory models. Proofs are phased: sequential semantics first, concurrency proofs later, with concurrent optimizations conservative until then and the assurance report stating it | Covers C/C++/Rust, VM languages, and GPUs, each with a published formal model; matches the state of the art in verified compilation (CompCert is sequential) |
| Op syntax | Each op is declared once, in Lean (`fir_ops` in `spec/Fir/Syntax.lean`): its fields, its names with their modifier vocabularies (`int.{op}.{ovf}`), its readable format as a template (`{ty} %, %, align {align}`), its typing rule as checks, and its effects. A macro generates the Lean `OpKind` and the op tables; `lake exe gen-rust` generates the Rust `OpKind` and the same tables into a checked-in file, which a test keeps current. Both parsers, printers, and verifiers interpret the tables. Every op also has a generic form, the same for all ops: `%s: i32 = "int.add.nsw"(%a, %b)`, with immediates as attributes (`"mem.load"(%p) {align = 4}`) and regions in parentheses (grammar in `spec/Fir/Parse.lean`). Operand and region counts are left to the verifier; an op the readable form can't show prints in the generic form, so everything that parses round-trips | Readable text without hand-written parsers; unknown and new dialect ops can round-trip; the two parsers can't drift apart, and adding an op is one declaration |
| Facts in text | In brackets between the result type and `=`, with a mandatory trust tag: `%p: ptr [nonnull proved, align(8) assume] = ...` | Facts sit next to the value they describe; deleting a bracket is always safe, matching the discardable-attribute rule |
| Locations in text | A short trailing `@line:col` on each op, with the file declared once per function (`loc "main.c"`). The printer can hide them (`--no-locs`), and text without them parses with an unknown location | Source mapping survives text tests and agent edits without cluttering every line |
| Holes | `?name: T` is a placeholder for a value that hasn't been written yet. A program with holes parses, verifies, and can be partly interpreted; tools report what each hole must satisfy (type, facts, effects). It can't be compiled to code | Lets people and agents write programs step by step with the checker guiding them; cheap now, hard to add to a grammar later |
| Untrusted producer, verified checker | Heuristic Rust code (analyses, optimizer passes, the register allocator) emits a certificate along with its result. A small checker, proved in Lean against the FIR semantics and compiled to C and linked into the binary, validates the certificate. If a check fails, the result is discarded and reported; for example, a `proved` fact that fails its check is dropped, which is always a safe refinement. Applied first to `proved` facts and to register allocation; passes without a certificate format keep using SMT translation validation. The assurance report states for each step whether it was proved, certificate-checked, SMT-validated, or trusted. This doesn't change FIR-0's scope, but FIR-0's refinement definition is written so later checkers can reuse it | Fast, complex heuristics stay in Rust and can change freely without proofs; only the small checker is trusted. A buggy producer can lose an optimization but can't cause a miscompile. CompCert validates its unverified register allocator the same way |
| Modifier spelling | Overflow modifiers that depend on signedness name it: `.s.trap`/`.u.trap`, `.s.sat`/`.u.sat`, `.s.ub`/`.u.ub`; `.nsw`, `.nuw`, `.nsw.nuw`, and `.wrap` stay as they are. Division and remainder have two edge cases, a zero divisor (`ub`, `trap`, or `total`) and signed `MIN / -1` (`ub`, `trap`, or `wrap`). One modifier covers both (`int.div.s.ub`, `int.div.s.trap`, `int.div.s.total`); two are written when they differ, e.g. Java's `int.div.s.trap.wrap`. `total` means `x / 0 = 0` and `x rem 0 = x`. Shifts by at least the width name `ub`, `trap`, `mask`, or `total` | Every edge case has a visible, named behavior; Java, Wasm, C, and Rust division each map to one spelling |
| Poison inputs | Poison in, poison out, except for ops that can trap or have UB on some inputs: there, a poison input that could hit the edge case is UB | An op can't decide whether to trap on an unknown value; keeps trapping ops precise |
| Fact semantics | A violated fact is UB whatever its trust tag; the tag only says how the compiler treats it (relied on, checked at runtime, or proved). Facts constrain defined values; `poison` passes | Dropping a fact and turning it into a runtime check are then both refinements, so facts stay discardable and sanitizer mode is sound |
| Formal semantics | A small-step machine with an explicit frame stack (and the trace of events so far, in the core). Values are bound in the frames: each region's block frame holds what its parameters and ops bound, a call starts with only its parameters, and a name is looked up in the current call's blocks, innermost first, so leaving a region drops its values. Ops on values and memory compute on the core (memory, scopes, oracle) from their operands' values; only the control layer reads operands and binds results. `freeze` picks values from an oracle, and the semantics quantifies over every oracle; external calls are answered by a world held fixed (Events, External call semantics). A function refines another when each of its behaviors refines some behavior of the other (Trace refinement). A `progress` loop that never exits is UB, defined as the machine never leaving that loop's frame after its last event: a loop that keeps calling external functions makes progress | Every intermediate state can be inspected; divergence and `progress` have exact definitions; the same machine extends to calls and concurrency. A value is visible exactly where the verifier allows a use, and proofs relate machines whose environments differ name by name without any invariant on core computations |
| Addresses | An allocation gets a numeric address lazily, the first time an address is observed: `ptr.addr`, `ptr.expose`, or an integer load of its pointer bytes (the quasi-concrete model, Kang et al., PLDI 2015). Until then it is purely logical and takes no address space. Observing an address is an effect: an unused `ptr.addr` can be deleted, an unused `ptr.expose` can't. If no address range is free, assigning one is UB | Allocation removal, stack promotion, and slot merging stay provable alongside integer casts; proofs never reason about placement or a full 32-bit space |
| Pointer comparison | `ptr.cmp.eq`/`ne` on in-bounds pointers into different allocations gives false; if either is one past the end, the result is nondeterministic. Ordered comparisons are defined within one allocation only; across allocations, programs compare `ptr.addr` values | Matches C, and comparisons never force an address to exist |
| Pointer bytes as integers | An `iN` load that reads pointer fragments exposes those pointers and returns their address bits; `poison` bytes still make the result `poison`. A `ptr` load of plain integer bytes acts as `ptr.from_exposed`, and gives back the original pointer only when its bytes are one pointer's fragments in order. The C frontend lowers `char` accesses and `memcpy` to `b8`. A dead integer load may be deleted only if it can't read pointer bytes or nothing later observes the exposure | Type punning through memory stays defined, as C requires (PNVI-ae), and byte copies never expose |
| Allocation failure | `mem.alloc.null` may return null (C `malloc`); `mem.alloc.trap` traps (Rust, Java). No default. Failure is a nondeterministic choice | Every edge case is named; removing an unused allocation stays a refinement |
| Pointer width | Each memory space declares a pointer size and an address (index) size, equal by default and 64 bits by default. The address size is what `ptr.addr`, `ptr.expose`, offsets, and allocation sizes use; the pointer size is how many bytes a pointer takes in memory. CHERI capabilities are 128/64, like LLVM's data-layout index size | One module can mix, e.g., 64-bit host pointers and 32-bit GPU-shared or Wasm pointers; capability hardware fits without special cases |
| Volatile | Reserved: `mem.load.volatile`/`mem.store.volatile` will be ops with the `extern` effect (never removed, duplicated, or reordered with other `extern` effects) whose every execution is an event in the same trace: the address, type, and stored value, and for a load the value the world answers (as CompCert's volatile events). Traces, trace refinement, and the simulation theorem need no change for them; only the event type gains a case | Device memory and signal handlers need it; no frontend does yet, and the trace model is what makes them precise |
| FIR-1 scope | Memory under the decisions above, plus direct calls between FIR functions, and external functions (decision: External functions). Headline proof: promoting stack slots to SSA values (mem2reg) for slots only loaded and stored at one type and never escaping, threading values through `cf.if` results and loop state. Also proved: store-to-load forwarding, dead stores, dead allocations, loads of fresh memory giving `poison`, and reordering across `noalias`, each with a rejected look-alike | mem2reg is the first optimization every C compiler runs and needs a whole-machine simulation proof, which every later memory proof reuses |
| Stack lifetime | `mem.stack` memory lives until its region ends: each loop iteration gets fresh memory, and a callee's memory ends when it returns | Matches C block scope; dangling stack pointers are caught at the exact access |
| Alignment rule | An access with `align N` is valid if its offset is a multiple of N and its allocation is aligned to at least N, or if the allocation already has an address and the accessed byte's address is a multiple of N. The check never assigns an address. The `align(N)` fact uses the same rule | Programs align by hand, e.g. rounding `malloc`'s result up to 32 for `_mm256_load_ps`; a purely symbolic rule rejects that, which is why Miri's symbolic alignment check is opt-in. Allocations without an address stay purely logical |
| Malformed sources | A source run that gets stuck (an undefined or out-of-scope variable, a value of the wrong type) is refined by anything, like UB. Stores check that the value has the op's type and get stuck otherwise | Verified programs never get stuck, so this only matters for programs the compiler never sees; rewrite proofs then don't need a typing invariant. Proving that verified programs never get stuck (type safety) is open |
| Simulation proofs | Program-level proofs go through one theorem (`Simulation.refines`): relate target states to source states and match each target step with one or more source steps, or with the source halting in UB; `SimulationS.refines` also lets a target step match none while an index decreases, for lowerings that expand one op into several. It handles halting, divergence, and `progress` loops once. Related states must have traces that match event by event, and a source escapes into UB only after events the target has already matched, so the theorem proves trace refinement, finite or infinite. Rewrites that change code but not what the core computes (dead stores, forwarding, copy propagation, dead code) reuse a lockstep layer (`StackRel`): machines with the same core, whose stacks hold the same code up to the rewrite and whose environments agree except on hidden names that no target code still to run reads, step together, so a proof only reasons about the rewritten spot. Dead code elimination hides the results of the ops it deletes. The spec keeps the core (memory, scopes, oracle) apart from the frame stack, which holds the environments, and stores memory in extensional maps, so equal contents are equal states | Each new optimization proof reasons about one step, not whole runs; dead store elimination is the first client |
| Aggregate values | HFIR only. Structs and arrays are values too: `agg.make %a, %b` (the result type says which), `agg.extract %s, i`, `agg.insert %s, %v, i` (constant indices), `copy`, and parameters, results, region parameters, block arguments, and call arguments of these types; external functions stay scalar (the ABI isn't decided). A value is the tuple of its parts (`RVal.agg`), with no aggregate `poison`: `poison` stays in the scalars. `mem.load` and `mem.store` of a struct, array, or slice type access its leaves (its scalars, fields depth first, `Ty.leaves`) one by one, each as a scalar access at `ptr.offset.wrap` by its offset with the alignment the offset keeps (`gcd(align, offset)`); padding is neither read nor written | A tuple keeps every value proof per scalar. Leaf-wise access is what scalarization emits, so lowering it is exact, and a store leaving padding unchanged is one of the values C allows for it (C11 6.2.6.1p6). In return a store of an aggregate doesn't overwrite an earlier store's padding bytes, so dead-store elimination and forwarding are stated for scalar stores (MFIR has no aggregate values) |
| Checked arithmetic | HFIR only: `int.add.overflow.s %a, %b` (and `sub`, `mul`, `.u`) gives `(iN, i1)`: the wrapped result, and whether the operation overflowed exactly when `int.add.s.trap` would trap. `poison` in gives `poison` for both. Language ops that trap on overflow are the existing `.s.trap` and `.u.trap` modifiers (reason `overflow`), in HFIR and MFIR | LLVM's `*.with.overflow` and Rust's `overflowing_*`, defined by the same overflow predicates as the trapping forms. One pair op serves branching, flag-setting, and saturating code; trapping needs no new op |
| Tagged unions | HFIR only. `union<T0, T1, …>` (at least one variant, each a value type) holds one variant and an `i32` tag naming it (`RVal.agg [tag, payload]`). `union.make %v, i`, `union.tag %u`, `union.get.ub %u, i` (another variant is UB, kind `tag`) and `union.get.trap %u, i` (a trap, reason `tag`). Unions are SSA values only for now: no layout, so they are not loaded, stored, or parts of structs and arrays | The edge-case vocabulary covers the wrong variant both ways. A union's memory form (tag size, niches, padding) belongs to the ABIs and languages that need it; as values they lower exactly to scalars |
| Slices | HFIR only. `slice` is a type, opaque like `ptr`: a pointer and an address-sized length counting elements, laid out as `struct<C>{ptr, iA}`. `slice.make %p, %n`, `slice.ptr`, `slice.len`, `slice.get.ub`/`.trap %s, %i, align N` (the result type is the element type, which may be an aggregate) and `slice.set.ub`/`.trap T %v, %s, %i, align N`. The index is unsigned; not below the length is UB (kind `bounds`) or a trap (reason `bounds`); a `poison` index or length is UB. The element is at `ptr.offset.inbounds` by the index times the stride, wrapped | One type for every language's slice or span; element types on the ops, as loads and stores carry theirs. Bounds checks are explicit and named, so the optimizer can remove proved ones |
| Checks | `cf.check.REASON %ok`, in HFIR and MFIR: nothing if `%ok` is 1, a trap with the reason (`bounds`, `tag`, `overflow`, `div0`, `shift`, `oom`) if 0, UB if `poison` | What HFIR's checks lower to: a flat op, so a check stays one step with no regions, and the trap is precise at it |
| Poison values | `poison` gives a `poison` value of any scalar type: `iN`, `ptr`, or `bN` (every byte `poison`) | A union's variants it doesn't hold lower to `poison` scalars of every type |
| HFIR lowering | `fir lower` and `fir-ref lower` (`Fir.Lower`) turn a verified HFIR module into a verified MFIR one, printing the same text. Each function is scalarized, then expanded. Scalarizing replaces every aggregate, union, or slice value by its scalars (`%s` of `struct<C>{i32, ptr}` becomes `%s.0`, `%s.1`; a union its tag then every variant's scalars, `poison` where it doesn't hold them; a hole the same hole at each scalar type), in parameters, results, region parameters, and the operands of branches, terminators, and calls, so functions pass aggregates as their scalars; the building blocks become copies, `int.const`, `poison`, checks (`int.cmp` and `cf.check`), `int.mul.wrap` and `ptr.offset`, and leaf accesses. Expanding turns checked arithmetic into extension to one more bit (twice the bits for `mul`), `.wrap` arithmetic, truncation, and a comparison of the exact result with the result extended back, and `ptr.field` and `ptr.index` into `ptr.offset` by `int.const` offsets and products (exact at twice the address size and `int.trunc.nsw` for `.inbounds`). Temporaries are `%.s0`, … and `%.e0`, …; lowering fails on field offsets that aren't positive signed addresses and in-bounds strides of at least `2^A` | Scalars are what MFIR, the optimizer, and register allocation work on. Copies keep each rewrite local (decision: Copies). The output is verified, so a name clash is reported, not miscompiled |
| Lowering proofs | `Lower.Proof.Expand.refines`: the expansion pass refines every function none of whose names is an expansion temporary and whose expanded ops take variables; `lowerFunc_refines` extends it to the whole lowering of functions that scalarizing leaves unchanged (no aggregate, union, or slice values). It goes through `SimulationS.refines`, the simulation theorem where a target step may also match no source step if an index decreases (one source op, several target ops), over the lockstep layer: at an expansion the source runs the op (failing only by getting stuck or UB) and the target runs the expansion (`RunsPure`), its temporaries hidden. Scalarizing is not proved yet: it renames each aggregate value to its scalars, which needs a code relation from source to target names and a leaf relation on environments (as copy propagation into regions needs) | The expansion proofs are one step each, on the arithmetic in `Fir.LowerBits`; the stuttering theorem is the "one step to many" half of the lowering's structure, reusable for every expansion |
| Copies | `copy %x` gives `%x`'s value, of any type, `poison` included. Rewrites produce copies instead of renaming uses (store-to-load forwarding turns a load into a copy of the stored value); copy propagation makes later uses read `%x`, and dead code elimination deletes the copy once nothing reads it | Each rewrite stays one local step proved in lockstep, and never reasons about renaming. Renaming is proved once, in copy propagation, and deleting once, in dead code elimination, with the environment relation mem2reg needs anyway. CompCert's `Omove` plays the same role |
| Passes | A pass is a plain Rust function over one function's body (or a module) that returns how many changes it made, with no state between runs; a pipeline runs named passes in order, the default `-O` one (`fwd`, `copyprop`, `dse`, `dce`) to a fixed point (`fir opt`). Each pass makes exactly the rewrite a Lean theorem proves, with the same side conditions, and its docs name the theorem and what it skips: `dse` (`Dse.refines`), `fwd` (`Fwd.refines`), `copyprop` (`CopyProp.refines`, as far as the run it allows reaches), `dce` (`Dce.refines`; which ops are `Pure` beyond copies, constants, and `poison` is read off `evalSimple`, not proved). Many rewrites are a chain of single instances, composed by `Func.Refines.trans`. Development builds verify after every pass and name the pass that broke the module. Each change can be recorded as a remark: the pass, the op, the op that justifies it, and a sentence (`dse: deleted store @3:5 (overwritten by @4:5)`) | Rewrites stay simple to match against their theorems until matching is by construction (certificates or generated matchers, after this round); plain functions serve the builder and C APIs unchanged. The remarks are the derivation side table of the Provenance decision and the seed of `--explain`. Differential testing (fixtures and random programs, original against optimized, by trace refinement in the interpreter) checks the composed result, including the steps not yet proved |
| Run invariants | Facts that hold for a whole run are proved once over the interpreter and carried in simulation relations. The first: no step changes the memory space and no step removes or changes an event (`Fir.Space`), so a proof can rely on the verifier's check that pointers take at least one byte, and a run's traces are prefixes of each other. Core computations can't see the environment, so no proof needs an invariant about it | Rewrite proofs stay about one step; the same approach will carry type safety |
| Ambiguous addresses | When an address from `ptr.from_exposed` fits several exposed (allocation, tag) pairs, the intended rule picks the one that avoids UB. Until that is implemented, the reference interpreter halts with the outcome `ambiguous` whenever the choice could matter: the pairs name different allocations, or an active `noalias` or `readonly` scope tells their tags apart. In refinement, an `ambiguous` target refines only UB and nothing refines an `ambiguous` source, so proofs cover only functions that never reach one | Picking one pair could report UB the intended rule wouldn't, and a false UB in the reference interpreter accepts miscompiles in differential testing |
| In-bounds offsets | `ptr.offset.inbounds` gives `poison` if the pointer or the result is outside `[0, size]` of a live allocation; an offset of 0 is always fine | Matches LLVM's `getelementptr inbounds`, which alias analysis relies on |
| Freeing null | `mem.free` of null does nothing, for every family | C `free(NULL)` and C++ `delete nullptr` are both no-ops |
| Byte order | Little-endian until data layouts are designed | Every mainstream target today |
| Tail calls | `func.call.tail` is guaranteed: it becomes a real tail call or compilation fails | Functional languages, Wasm tail calls, fast threaded interpreters for the VM kit |
| Attributes | Two kinds, enforced by the verifier. *Semantic* attributes change meaning and are never dropped. *Discardable* attributes (hints, metadata, facts) are always safe to drop | Gives passes a simple rule. Dropping a fact only makes a program more defined, so it is always a refinement |

## Open

Ordered by dependency.

### AOT phase (now)

0. FIR-1 program-level proofs: the simulation framework, dead store elimination, store-to-load forwarding, copy propagation through straight-line code (the ops after a copy in its block, up to the first region or call), and dead code elimination (deleting copies, constants, and `poison` that no later op in their region reads, at any depth, across calls) are proved, as is the HFIR lowering's expansion pass (checked arithmetic, `ptr.field`, `ptr.index`). Next for the lowering: scalarizing (decision: Lowering proofs), and then the whole lowering of a module, whose functions call each other's lowerings (a refinement between two modules). Next: copy propagation into regions and across calls (needs a code relation that substitutes operands, with `%x` and `%y` agreeing in every frame that runs substituted code, and frames below a call related by the proof's own relation), mem2reg (also needs a relation between memories, and hidden names that rewritten target code reads), dead allocations, and reordering across `noalias`. Also: the angelic choice for ambiguous addresses, replacing the `ambiguous` outcome; type safety (verified programs never get stuck)
1. Structure details: symbol visibility and linkage, external globals; for external functions: callbacks into the module (passing a function pointer to `qsort` today lets the world call nothing), recording a callee's writes in `noalias` scopes, a `nocapture`-like effect so passing a pointer needn't expose it, facts on parameters and results of declarations, and volatile events; named (and recursive) types so large structs aren't repeated, initializers that point inside a global (`&a[3]` needs a field and index path, not byte offsets), graph (unordered) regions for dataflow hardware
2. Control flow details: coroutines, async, and generators (an HFIR building block lowered to a state machine; decided in the building-blocks round)
3. Types details: closure types; unions in memory (a tag size and layout, niches); dynamic indices into array values; aggregate parameters of external functions (with the ABI)
4. ABI: C calling conventions, owned by FIR. AAPCS64 for integers and pointers is decided (Calling convention); next: aggregates by value (HFAs, composites up to 16 bytes in registers), `i128` in register pairs, floats, varargs, and macOS's variant (packed stack arguments, extended narrow arguments)
5. Representations: ops are declared once and the parsers, printers, typing rules, and Rust `OpKind`, and builder methods (Rust and C) come from the declarations (see Op syntax; the Rust implementation is checked against `fir-ref fmt --unverified` and `fir-ref check` on every test file: same output, or the same error; the Rust interpreter, `fir run`, is checked against `fir-ref run` on every `// run:` line and on random well-typed programs, for the oracle that always answers 0 and the world that answers every external call with zeros). Layers and dialects are declared per op and enforced (decisions: Layers, Dialects). Next: generic ops whose names `OpKind` doesn't know, for dialects (the generic form parses only known ops for now); naming the target in MFIR, so that the target legality rule can admit a target's ops there (`layer mfir` names none yet, and no op is in MFIR and a target's dialect); using the declared effects and trust tiers, which nothing reads yet; Rust limits that Lean doesn't have (sizes and array lengths are 64-bit; alignments, widths, field indices, memory-space sizes, and locations 32-bit; `fir run` takes address sizes up to 64 bits); binary format; versioning
6. Transformations: the pass manager and the four proved rewrites as passes exist (decision: Passes; `crates/fir/src/passes/`), checked by differential testing against the original program on every fixture and on random programs. Next: matching each pass to its proof by construction; proving that rewrites compose (intermediate programs stay `Decided`, and refining a callee refines its callers, so a whole module can be optimized); proving `Pure` for the ops `dce` deletes beyond copies, constants, and `poison`; copy propagation into regions and across calls once proved (item 0); analyses, a rule DSL, incremental compilation; the proved restructuring of `cf.blocks` into `cf.if` and `cf.loop` (decision: Control flow)
7. Lowering: target description format, ISA semantics sources (AArch64's from Arm's ASL), debug info. AArch64 isel and register allocation are decided (Instruction selection, Register allocation); next: the allocator's Lean-proved checker, isel rules checked against the ASL semantics, coalescing and lifetime holes, folding offsets and shifted operands, jump tables, `madd`/`ldp`/`stp` (a wider `OpKind` or side tables), exceptions' unwind tables, and guaranteed tail calls (`func.call.tail`)
8. AOT driver: `fir compile` is decided (AOT driver); next: an object file writer, the pass pipeline in front of isel, HFIR lowering in the driver, and a runtime library (traps that raise language exceptions)
